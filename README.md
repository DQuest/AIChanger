# AIChanger

Удержание кнопки питания вызывает **Gemini** вместо BlueLM на vivo X200 Ultra (OriginOS 6, Android 16, без root).

## Как это работает

- Системный ассистент на телефоне и так Google/Gemini, но vivo перехватывает удержание питания раньше системы
  и запускает BlueLM (`com.vivo.ai.copilot`), если `system vivo_jovi_power_wakeup_switch=1`.
- Штатная настройка Android `global power_button_long_press` прошивкой vivo игнорируется, а фабрикация
  оверлеев без root запрещена. Поэтому нужна прослойка.
- Приложение запускает через Shizuku службу с uid shell (`PowerKeyService`), которая:
  1. выставляет `vivo_jovi_power_wakeup_switch=0`, и BlueLM больше не срабатывает;
  2. читает события кнопки питания из `/dev/input/eventN` (устройство `pmic_pwrkey`, номер меняется между загрузками);
  3. при удержании ≥ 600 мс закрывает системные диалоги и отправляет `KEYCODE_ASSIST`, открывая настоящий оверлей Gemini;
  4. на экране блокировки сначала запрашивает разблокировку (`wm dismiss-keyguard`), потому что экран блокировки vivo
     не пропускает панель Gemini, а после разблокировки открывает Gemini;
  5. проверяет, что панель Gemini действительно открылась, и при необходимости повторяет вызов
     (сразу после первой разблокировки Google-приложение ещё поднимается).
- Меню питания vivo по-прежнему доступно: оно появляется при удержании кнопки около 2,5 с, если не сработал Gemini,
  а также есть в шторке.

## Установка

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

vivo просит подтвердить установку по adb на экране телефона, поэтому телефон должен быть разблокирован.

В приложении нажмите «Выдать доступ Shizuku», затем «Включить».

## Автозапуск после перезагрузки

Shizuku без root после перезагрузки не работает, а его штатный автозапуск есть только для root.
Поэтому AIChanger запускает его сам: при загрузке (ещё до первой разблокировки) дожидается Wi-Fi,
включает беспроводную отладку, подключается к своему adbd ключом, сопряжённым заранее, запускает
`libshizuku.so`, затем выключает беспроводную отладку обратно. Shizuku сам будит AIChanger,
и служба кнопки поднимается. В тестах всё было готово через 5 с после загрузки.

Разовая настройка:

1. Выдать разрешение на запись системных настроек:
   ```bash
   adb shell pm grant dev.dquest.aichanger android.permission.WRITE_SECURE_SETTINGS
   ```
2. В vivo разрешить автозапуск AIChanger: «Автозапуск» (`com.vivo.permissionmanager/.activity.BgStartUpManagerActivity`).
   Без этого vivo отбрасывает загрузочную рассылку (`skip for auto start`).
3. В AIChanger: «Сопряжение с беспроводной отладкой» → включить «Беспроводная отладка» с галочкой
   «Всегда разрешать в этой сети» → «Сопряжение по коду» → в уведомлении AIChanger «Ввести код».
   Если кнопка «Ввести код» не появилась, вернитесь в приложение и нажмите «Сопряжение» ещё раз.
4. В AIChanger: «Включить автозапуск». Проверить без перезагрузки можно кнопкой «Запустить Shizuku сейчас».

Ограничения: нужен Wi-Fi, для которого разрешена беспроводная отладка. В другой сети или без Wi-Fi
автозапуск не сработает (придёт уведомление с ошибкой), и тогда Shizuku можно запустить вручную, в том числе с компьютера:

```bash
adb shell "$(adb shell pm path moe.shizuku.privileged.api | head -1 | sed 's/^package://;s/base.apk//' | tr -d '\r')lib/arm64/libshizuku.so"
```

Пока Shizuku не запущен, удержание кнопки открывает меню питания; BlueLM остаётся выключенным.

## Откат

Кнопки «Выключить автозапуск» и «Выключить (вернуть BlueLM)» в приложении. Вручную:

```bash
adb shell content insert --uri content://settings/system --bind name:s:vivo_jovi_power_wakeup_switch --bind value:s:1
adb shell content insert --uri content://settings/global --bind name:s:power_button_long_press --bind value:s:1
```

Исходные значения сохранены в `backup.txt`. Замечание: на этой прошивке `settings put` для этих ключей молча
не срабатывает, записывать нужно через `content insert`.
