# AIChanger

Удержание кнопки питания вызывает **Gemini** или другого ИИ-ассистента (Claude, ChatGPT, Perplexity, Алиса)
вместо BlueLM на телефонах vivo с OriginOS 6 (Android 16, без root).
Ставится одно приложение. Shizuku и компьютер не нужны.

## Как это работает

- Системный ассистент на телефоне и так Google/Gemini, но vivo перехватывает удержание питания раньше системы
  и запускает BlueLM (`com.vivo.ai.copilot`), если `system vivo_jovi_power_wakeup_switch=1`.
- Штатная настройка Android `global power_button_long_press` прошивкой vivo игнорируется, поэтому нужна прослойка.
- Нужны права uid shell. Приложение получает их через собственный adb: оно само сопрягается с беспроводной
  отладкой (как Shizuku), подключается к своему adbd и запускает демон
  `app_process … dev.dquest.aichanger.daemon.PowerKeyDaemon` (процесс `aichanger-daemon`).
  Потом беспроводная отладка выключается, а демон продолжает работать.
- Демон ([PowerKeyEngine](app/src/main/java/dev/dquest/aichanger/daemon/PowerKeyEngine.kt)):
  1. выставляет `vivo_jovi_power_wakeup_switch=0`, и BlueLM больше не срабатывает;
  2. читает события кнопки питания из `/dev/input/eventN` (устройство `pmic_pwrkey`, номер меняется между загрузками);
  3. при удержании ≥ 600 мс открывает выбранного в приложении ассистента (см. ниже);
  4. на экране блокировки сначала запрашивает разблокировку (`wm dismiss-keyguard`), потому что экран блокировки vivo
     не пропускает панель Gemini, а после разблокировки открывает ассистента;
  5. проверяет, что ассистент действительно открылся, и при необходимости повторяет вызов;
  6. если кнопку держать ~2 с, закрывает ассистента и открывает меню питания vivo (`input keyevent --longpress KEYCODE_POWER`).
- Ассистенты. В списке только приложения со своей службой голосового ассистента (VoiceInteractionService):
  они открываются поверх экрана. Приложения без неё (например, DeepSeek) не показываются.
  - **Gemini** вызывается через системного ассистента (Google). Режим выбирается в приложении: «Сразу голосовой ввод»
    (`KEYCODE_VOICE_ASSIST`, по умолчанию, как на Samsung) или «Окно Gemini без прослушивания» (`KEYCODE_ASSIST`).
  - **Claude, Perplexity, Алиса** запускаются напрямую через их режим ассистента (`am start -a android.intent.action.ASSIST`),
    системный ассистент телефона не меняется. Слушать они начинают сразу.
  - **ChatGPT** работает только как системный ассистент, поэтому при его выборе AIChanger делает его ассистентом
    телефона (`cmd role`). Прежний ассистент возвращается при выборе другого, выключении перехвата или удалении AIChanger.
- Приложение общается с демоном по `127.0.0.1:47831` с секретным токеном
  ([DaemonProtocol](app/src/main/java/dev/dquest/aichanger/daemon/DaemonProtocol.kt)).
  Если приложение удалить, демон через ~10 с вернёт BlueLM (и прежнего системного ассистента) и завершится сам.
- Порт беспроводной отладки приложение находит само, перебором локальных портов: mDNS на телефоне ненадёжен.

## Установка

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

vivo просит подтвердить установку по adb на экране телефона, поэтому телефон должен быть разблокирован.
Можно также просто скопировать APK на телефон и установить.

## Настройка (один раз)

1. Включить «Параметры разработчика» (7 нажатий на номер версии ПО).
2. В AIChanger нажать «Включить». Откроются настройки для разработчиков и появится уведомление AIChanger с полем кода.
3. Включить «Беспроводная отладка», отметить «Всегда разрешать в этой сети», выбрать «Сопряжение по коду»
   и ввести показанный код в уведомлении AIChanger. Если приложение попросит порт, ввести «порт код» через пробел.
4. Готово: перехват запускается сам. Ассистента можно выбрать в разделе «Ассистент». При первом запуске приложение выдаёт себе `WRITE_SECURE_SETTINGS`,
   чтобы дальше включать беспроводную отладку без участия пользователя.
5. Нажать «Разрешить автозапуск (vivo)» и включить AIChanger. Без этого vivo отбрасывает загрузочную
   рассылку (`skip for auto start`) и демон не стартует после перезагрузки.

После этого беспроводную отладку и даже параметры разработчика можно выключить: приложение включает их
на пару секунд при запуске демона и возвращает как было.

## Автозапуск

После перезагрузки (ещё до первой разблокировки) и после обновления приложение дожидается Wi-Fi, запускает
демон и снова выключает отладку. В тестах всё было готово через ~5 с после загрузки. Если автозапуск
не сработал (не было Wi-Fi, vivo не разбудила приложение, демон убит), достаточно открыть AIChanger:
он сам перезапустит демон.

Ограничение: нужен Wi-Fi, для которого разрешено «Всегда разрешать в этой сети». В другой сети или без Wi-Fi
демон не запустится (придёт уведомление с ошибкой), и удержание кнопки откроет меню питания vivo; BlueLM
остаётся выключенным.

## Откат

Кнопка «Выключить (вернуть BlueLM)» в приложении или удаление приложения. Вручную:

```bash
adb shell content insert --uri content://settings/system --bind name:s:vivo_jovi_power_wakeup_switch --bind value:s:1
adb shell cmd role add-role-holder android.app.role.ASSISTANT com.google.android.googlequicksearchbox 0
```

Исходные значения сохранены в `backup.txt`. Замечание: в OriginOS `settings put` для этих ключей молча
не срабатывает, записывать нужно через `content insert`.
