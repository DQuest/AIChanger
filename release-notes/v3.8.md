## Русский

Первый релиз на GitHub. Удержание кнопки питания на vivo с OriginOS 6 открывает Gemini, Claude, ChatGPT,
Perplexity или Алису вместо BlueLM. Ниже — что изменилось с версии 3.4.

### Главное

- **BlueLM AIChanger больше не трогает.** Вызов BlueLM кнопкой питания выключаете вы сами (первый шаг мастера
  настройки), и вы же включаете его обратно, если он нужен. Раньше приложение переключало скрытую настройку vivo
  и перекрывало ваш выбор.
- **Надёжнее служба.** Она больше не падает от «молчащего» или оборванного подключения к своему порту, не тратит
  память на чужие подключения и не принимает от них ничего, кроме имён пакетов. Каждый запуск службы получает
  новый токен.
- **Выключение не путается с запуском.** Если выключить AIChanger, пока он запускается, служба больше не поднимется
  после выключения. Если прежнего системного ассистента вернуть не удалось (службы нет, а Wi-Fi нет), это видно на
  главном экране, и попытка повторится при следующем открытии.

### Кнопка и ассистенты

- Повторное нажатие отменяет запоздалый вызов ассистента: экран, который вы только что погасили, больше не
  включится сам.
- Питание вместе с громкостью (скриншот и другие сочетания) ассистента не вызывает.
- Меню питания по долгому удержанию не задерживается, пока ассистент открывается.
- Gemini распознаётся, даже если Google переименует его окно; повтор вызова остался только для Gemini, остальные
  ассистенты вызываются один раз и не закрываются повторной клавишей.
- Если ассистента обновили (сменилось окно) или удалили, выбор поправится сам при открытии приложения.
- Подсказка о смене системного ассистента показывается, только когда AIChanger действительно его поменял.
- Кнопка питания ищется по возможностям устройства, а не по одному имени: поддержаны и другие чипы Qualcomm и MediaTek.

### Wi-Fi и настройка

- В сети, где беспроводная отладка не разрешена, AIChanger понимает это за несколько секунд (раньше — около двух
  минут и пять системных диалогов) и ждёт с уведомлением «Другая сеть Wi-Fi» подключения к нужной сети.
- Мастер настройки продолжается с того же шага после возврата из настроек телефона или по уведомлению.
- «Настроить заново» больше не отключает автозапуск, если мастер бросить на середине.
- При сопряжении можно вставить строку «IP-адрес и порт» целиком.
- Уведомления о запуске стали тихими и больше не остаются висеть после выключения.
- Данные приложения не попадают в резервные копии и перенос на другой телефон: ключ сопряжения действует только
  на этом устройстве.

### Прочее

- Ложное «приложение удалено» (сбой `pm`) больше не останавливает перехват.
- Ключ сопряжения записывается так, что прерванная запись его не портит.
- Сборка, юнит-тесты и выпуск релизов — в GitHub Actions.

### Установка

Скачайте `AIChanger-v3.8.apk` ниже и установите. APK подписан тем же отладочным ключом, что и локальные сборки
разработчика, поэтому ставится поверх них. Если раньше вы ставили сборку с другой подписью, Android сообщит о
несовпадении: тогда выключите AIChanger, удалите его и установите заново, пройдя сопряжение ещё раз.

После обновления с версии, которая сама выключала BlueLM, проверьте в настройках телефона, что вызов BlueLM
кнопкой питания выключен: AIChanger больше этим не управляет.

## English

The first release on GitHub. Holding the power button on vivo phones with OriginOS 6 opens Gemini, Claude, ChatGPT,
Perplexity or Alice instead of BlueLM. Here is what changed since version 3.4.

### Highlights

- **AIChanger no longer touches BlueLM.** You turn off BlueLM on the power button yourself (the first step of the
  setup wizard) and turn it back on if you want it. Previously the app flipped a hidden vivo setting and overrode
  your choice.
- **A more reliable service.** It no longer crashes on a silent or dropped connection to its port, doesn't waste
  memory on foreign connections and accepts nothing from them but package names. Every service start gets a new
  token.
- **Turning off no longer races with starting.** If you turn AIChanger off while it is starting, the service won't
  come up afterwards. If the previous system assistant couldn't be restored (no service and no Wi-Fi), the main
  screen says so and the app retries the next time it opens.

### Power button and assistants

- Pressing the button again cancels a late assistant call: a screen you just turned off no longer turns on by itself.
- Power together with volume (screenshot and other combos) no longer invokes the assistant.
- The power menu on a long hold isn't delayed while the assistant is opening.
- Gemini is recognized even if Google renames its window; only Gemini is retried now, other assistants are invoked
  once and aren't closed by a repeated key.
- If an assistant is updated (its window renamed) or uninstalled, the choice fixes itself when the app opens.
- The note about changing the system assistant shows only when AIChanger has actually changed it.
- The power key is found by device capabilities rather than one name, so other Qualcomm and MediaTek chips work too.

### Wi-Fi and setup

- On a network where wireless debugging isn't allowed, AIChanger notices within seconds (it used to take about two
  minutes and five system dialogs) and waits for the right network with an "Another Wi-Fi network" notification.
- The setup wizard resumes at the same step after you come back from the phone settings or a notification.
- "Set up again" no longer disables autostart if you abandon the wizard halfway.
- When pairing you can paste the whole "IP address & port" line.
- Startup notifications are silent now and no longer linger after turning off.
- App data is kept out of backups and device transfers: the pairing key only works on this device.

### Other

- A false "app uninstalled" (a `pm` hiccup) no longer stops the interception.
- The pairing key is written so that an interrupted write can't corrupt it.
- Builds and unit tests run in GitHub Actions, and releases are published from it.

### Installation

Download `AIChanger-v3.8.apk` below and install it. The APK is signed with the same debug key as the developer's
local builds, so it installs over them. If you previously installed a build with a different signature, Android will
report a mismatch: turn AIChanger off, uninstall it and install again, pairing once more.

After updating from a version that turned BlueLM off by itself, check in the phone settings that BlueLM on the power
button is off: AIChanger no longer manages it.
