# CLAUDE.md

AIChanger: удержание кнопки питания на телефонах vivo с OriginOS 6 (Android 16, без root) открывает Gemini
или другого ИИ-ассистента (Claude, ChatGPT, Perplexity, Алиса) вместо BlueLM.
Пользовательское описание и настройка: [README.md](README.md).

## Сборка и установка

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

- vivo требует подтвердить установку по adb на экране: телефон должен быть разблокирован, иначе `INSTALL_FAILED_ABORTED: User rejected permissions`.
- Юнит-тесты (`./gradlew :app:testDebugUnitTest`) покрывают только чистые функции: проверку имён в протоколе,
  чтение команды демоном, разбор ввода при сопряжении. Остальное проверяется на устройстве (см. «Отладка»).
- CI: `.github/workflows/build.yml` гоняет тесты и собирает `assembleDebug` на каждый push и PR, APK — в артефактах запуска.
  Релиз: поднять `versionName`, положить описание в `release-notes/v<версия>.md` и запушить тег `v<версия>`
  или запустить workflow вручную на `main` (Run workflow) — он создаст тег и релиз с этим APK. Если релиз этой версии
  уже есть, повторный запуск только обновит его описание из `release-notes/`.
  Секрет `CHANGERKEY` — debug-ключ разработчика (keystore в base64), чтобы APK из CI ставился поверх локальной сборки.
- Сборка только под `arm64-v8a` (нативные библиотеки conscrypt под другие ABI не нужны), minSdk 30, targetSdk 36.

## Архитектура

Два процесса из одного APK:

- **Приложение** (`dev.dquest.aichanger`): UI, сопряжение, запуск демона.
  - `MainActivity`: реализует `ui.UiActions` (сопряжение, автозапуск, выбор ассистента) и показывает экраны из `ui/`
    на Jetpack Compose + Material 3: `SetupWizard` (первая настройка, пока нет сопряжения или не пройден шаг
    автозапуска, `setup_done`; первый шаг — пользователь сам выключает BlueLM на кнопке; отметки пользователя
    хранятся в `setup_steps`, чтобы мастер продолжался и после возврата по уведомлению) и `HomeScreen` (карточки). `UiState` — снимок `PowerKeyController`, перечитывается по счётчику.
  - `PairingService`: сопряжение с беспроводной отладкой, код вводится в уведомлении (RemoteInput); канал уведомлений
    громкий, чтобы поле кода всплыло поверх настроек. Статус автозапуска — в отдельном тихом канале.
  - `AdbManager`: ключ и сертификат adb-клиента на libadb-android, хранятся в Device Protected storage.
  - `DaemonLauncher`: включает беспроводную отладку (и при необходимости параметры разработчика), подключается к своему adbd,
    при первом запуске выдаёт себе `WRITE_SECURE_SETTINGS`, стартует демон через `app_process`, возвращает настройки как были.
  - `PowerKeyController`: настройки и состояние, `ensureRunning` запускает демон, если не отвечает демон текущей версии.
  - `BootReceiver` + `AutoStartService`: автозапуск после загрузки (до первой разблокировки) и после обновления.
    Поток запуска может пережить экземпляр службы («Выключить» её останавливает), поэтому службу и уведомление
    по его окончании убирает главный поток, а поток работает с контекстом приложения.
  - `DaemonClient`: клиент протокола.
  - `Assistants`: список ассистентов — приложения с VoiceInteractionService; для каждого способ вызова
    (`target`: пакет системного ассистента или `пакет/activity` для прямого запуска ASSIST).
- **Демон** (`daemon/`, процесс `aichanger-daemon`, uid shell):
  - `PowerKeyDaemon`: точка входа `main`, TCP-сервер `127.0.0.1:47831` с токеном, следит за удалением приложения.
  - `PowerKeyEngine`: читает `/dev/input` (кнопку питания и громкости), по удержанию вызывает ассистента (клавиша ASSIST
    для системного ассистента или `am start` его activity), по ~2 с открывает меню питания. Питание вместе с громкостью —
    сочетание (скриншот), тогда ничего не делает. Меняет роль системного ассистента, если выбранный работает только так,
    и помнит, кого вернуть.
  - `DaemonProtocol`: общие константы и команды (`ping`, `status`, `problem`, `mode`, `assistant`, `stop`).

Правила, которые легко нарушить:

- **Меняете код демона — поднимайте `versionCode`** в `app/build.gradle.kts`. Приложение перезапускает демон, только если `ping` вернул другую версию.
- Код в `daemon/` работает вне приложения: там нет `Context`, Android API доступны только те, что работают из `app_process`
  с uid shell. Системные действия выполняются shell-командами (`sh(...)`).
- К порту демона может подключиться любое приложение. Всё, что пришло по протоколу (пакеты, activity), демон проверяет
  (`DaemonProtocol.isValidTarget`/`isValidRestore`) и передаёт в команды только через `exec(listOf(...))`, не через `sh`.
  Токен новый при каждом запуске демона (`PowerKeyController.newToken`).
- Необработанное исключение в любом потоке демона убивает весь процесс (`app_process` ставит `KillApplicationHandler`),
  и кнопка остаётся без ассистента. Код в потоках демона ловит всё сам.
- Запуск (`ensureRunning`) и остановка (`stopDaemon`) идут под одним локом `PowerKeyController`: остановка службы
  не прерывает её поток, а `AdbManager` общий.
- Всё, что нужно до первой разблокировки, должно быть `directBootAware` **на каждом компоненте** (флаг у `<application>`
  на компоненты не распространяется) и хранить данные в `createDeviceProtectedStorageContext()`.
- Команда запуска демона через libadb должна заканчиваться `& sleep 1`: `shell:` идёт через PTY, и без паузы фоновый
  процесс гибнет от hangup раньше, чем `setsid` его отвяжет. В конце потока libadb бросает «Stream closed» вместо -1.
- BlueLM приложение не трогает ни при запуске, ни при выключении: вызов BlueLM кнопкой питания пользователь
  выключает и включает сам (первый шаг `SetupWizard`).
- Демон переживает удаление приложения (uid shell), поэтому сам возвращает прежнего системного ассистента
  и завершается (`watchForUninstall`). То же при команде `stop`. Кого вернуть, приложение хранит в настройках
  (`restore_role`) и передаёт демону командой `assistant` после каждого запуска.
- В недоверенной сети система сразу сбрасывает `adb_wifi_enabled` и показывает диалог о разрешении отладки.
  Сброс сразу после загрузки бывает и в доверенной (Wi-Fi ещё не готов), поэтому `DaemonLauncher` перезапускает отладку
  один раз, а после второго сброса бросает `UntrustedWifiException`: `AutoStartService` ждёт другую сеть,
  а не повторяет попытки в этой.
- Для прямого запуска `assistant` хранит и activity, а обновление ассистента может её переименовать. `MainActivity.onStart`
  сверяет выбор со списком ассистентов (`reconcileAssistant`); до разблокировки список неполный, там сверять нельзя.
- «Настроить заново» не сбрасывает `paired` (`isRepairing` только в памяти): ключ продолжает действовать, и если мастер
  бросить, автозапуск после перезагрузки должен работать.
- Если при выключении демона нет, а вернуть прежнего системного ассистента через adb не вышло, `restore_role` остаётся,
  ошибка (`lastStopError`) видна на главном экране, и `startIfNeeded` повторяет возврат при следующем открытии.
- Повтор вызова ассистента нужен только Gemini (панель закрывается сама сразу после загрузки); остальных повторная
  клавиша или `am start` закрыла бы или открыла заново.
- Настройки отладки, которые включило приложение, отмечаются в `launcher_marks`: если процесс убьют посреди запуска
  (например, обновлением), следующий запуск их всё равно вернёт.

## Особенности OriginOS

- `settings put` для нужных ключей молча не работает. Писать через
  `content insert --uri content://settings/<ns> --bind name:s:K --bind value:s:V`.
- BlueLM на кнопке выключается `system vivo_jovi_power_wakeup_switch=0`, включается `=1` (приложение этот ключ не трогает).
  `global power_button_long_press` прошивка игнорирует.
- Экран блокировки vivo не пропускает панель Gemini (видна только подсветка): сначала `wm dismiss-keyguard`, затем ASSIST.
- Любая инжектированная клавиша во время удержания питания помечает нажатие обработанным, иначе отпускание гасит экран
  (на экране блокировки для этого шлётся `KEYCODE_WAKEUP`).
- Меню питания из shell: `input keyevent --longpress KEYCODE_POWER`.
- vivo отбрасывает загрузочные рассылки (`skip for auto start`), пока приложение не включено в
  `com.vivo.permissionmanager/.activity.BgStartUpManagerActivity`. Поэтому `MainActivity.onStart` тоже запускает демон при необходимости.
- vivo замораживает фоновые приложения (`am_app_frozen … from fast_freezer` в `logcat -b events`) через секунды после
  ухода с экрана, foreground-служба не спасает, а запущенное задание JobScheduler vivo при заморозке отменяет.
  Исключение — «Разрешить высокое энергопотребление» в `com.iqoo.powersaving/.BackgroundHighUsageActivity` (шаг мастера).
  Без него `AutoStartService`, ждущая Wi-Fi, засыпает навсегда. Демон (uid shell) не замораживается.
- Номер `/dev/input/eventN` меняется между загрузками. Кнопка питания ищется по имени (`pmic_pwrkey` на Qualcomm,
  на MediaTek другое — список в `PowerKeyEngine`), иначе — любое не uinput-устройство с `KEY_POWER` в `getevent -pl`.
  Громкость может быть на других устройствах; её отпускание может потеряться при переоткрытии, поэтому громкость
  считается частью сочетания, только если нажата не раньше чем за 1 с до питания.
- Доверенные сети беспроводной отладки хранятся по BSSID.
- mDNS на телефоне ненадёжен: после перезапуска отладки остаётся устаревшая запись, а системный клиент mDNS не разбирает
  часть пакетов (`Error while decoding multicast packet`). `service.adb.tls.port` приложениям (и shell) закрыт.
  Поэтому `DaemonLauncher` ищет порт перебором 127.0.0.1 в `ip_local_port_range` (32768–60999, неблокирующие сокеты)
  и проверяет его пакетом CNXN (adbd отвечает STLS); mDNS остаётся запасным путём.
- Прямой запуск ассистента (`am start`) клавиш не нажимает, поэтому перед ним шлётся `KEYCODE_WAKEUP`: иначе отпускание
  кнопки питания погасит экран.
- ChatGPT: `AssistantProxyActivity` при прямом запуске сразу закрывается, работает только как системный ассистент.
  Claude, Perplexity и Алиса при прямом запуске открывают свою панель и сразу слушают.
- USB-отладка в OriginOS продолжает работать и при выключенных параметрах разработчика.
- Нижний бар рисует лаунчер vivo (`com.bbk.launcher2`, окно `Taskbar`), а не SystemUI, поэтому `LONG_PRESS_HOME_ASSIST`
  из политики окон не срабатывает. Удержание «Домой» лаунчер обрабатывает сам (`db.p0.p` в его коде): на глобальной прошивке
  (`ro.vivo.product.overseas` не `no`) вызывает системного ассистента (`startAssistant`, `invocation_type=5`) или Circle to Search,
  на китайской — только BlueLM (`global system_navigation_wake_up_switch`), без него ничего. Поэтому на китайской OriginOS
  ассистента вызывает только кнопка питания, и роль системного ассистента нужна только ChatGPT. На глобальной смена роли
  перенесла бы выбор и на «Домой» (не проверено).
- Claude в роли системного ассистента на `KEYCODE_ASSIST` ничего не показывает (служба привязана), только прямой запуск.
  ChatGPT, Perplexity и Алиса в роли открывают свою панель.

## Отладка

```bash
adb shell pidof aichanger-daemon                       # демон жив?
adb shell ps -A -o PID,STIME,NAME | grep aichanger     # когда запущен
adb logcat -s AIChanger                                # логи приложения и демона
adb shell dumpsys activity activities | grep -m1 topResumedActivity   # открыт ли Gemini (FloatyActivity)
```

- При включённой беспроводной отладке adb на Mac видит второе устройство; выбирать USB через `ANDROID_SERIAL`.
- Откат BlueLM вручную: `adb shell content insert --uri content://settings/system --bind name:s:vivo_jovi_power_wakeup_switch --bind value:s:1`.
- `prototype/power_to_gemini.py` — первый прототип логики, работает с Mac по adb; `backup.txt` — исходные значения настроек.

## Иконка

`res/drawable-nodpi/ic_launcher_art.png` — весь слой адаптивной иконки (432 px = 108 dp): рисунок занимает видимое окно
72 dp, поля вокруг — продолжение его краёв под маску лаунчера. `ic_app_art.png` — видимая часть для заголовка в приложении.
Исходник — картинка от пользователя; при замене нужно так же срезать фон, тень и ободок.

## Стиль

- Интерфейс и комментарии на русском. Комментарии объясняют «почему», особенно обходы прошивки vivo.
- README на двух языках: `README.md` по-русски, `README.en.md` по-английски, меняются вместе. Описание релиза
  `release-notes/v<версия>.md` — один файл: сначала раздел на русском, затем `## English`.
- Сообщения коммитов на английском: заголовок в повелительном наклонении и тело с причиной.
- Версии зависимостей в `gradle/libs.versions.toml`; libadb-android берётся с JitPack (ограничено группой в `settings.gradle.kts`).
